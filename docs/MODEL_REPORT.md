# Flowline Hazard Forecast — Model Report

Generated by `scripts/evaluate.py` on 2026-10-05. Forecasts are based on historical public incident data. Flowline supports engineering judgment; it does not certify any pipe as safe.

## 0. Conclusion (plain words)
- **Canada:** the full model **beats** the best baseline (*Baseline: province base rate*) on log loss: Δ = -0.151, 95% CI [-0.198, -0.105] (n = 430).
- **Alberta:** the full model **beats** the best baseline (*Baseline: national base rate*) on log loss: Δ = -0.069, 95% CI [-0.127, -0.009] (n = 164).
- **Weather features, Canada:** makes no measurable difference (Δ log loss full − without = +0.003, 95% CI [-0.024, +0.028]).
- **Weather features, Alberta:** makes no measurable difference (Δ log loss full − without = +0.012, 95% CI [-0.028, +0.056]).
- **Area history features, Canada:** helps (Δ log loss full − without = -0.068, 95% CI [-0.100, -0.038]).
- **Area history features, Alberta:** helps (Δ log loss full − without = -0.051, 95% CI [-0.101, -0.001]).
- **Reading the weather result:** a weather signal exists in the raw data (§6: post-2022 Alberta washouts followed wetter months than other incidents), but the model cannot learn it from the training years, when geotechnical incidents were rare in Alberta. Raw station totals also mix climate with weather. Likely next steps: precipitation *anomaly* versus each station's normal, river-crossing and slope proximity, and more years of data — all to be judged on the rolling-origin check, never on the test set.

## 1. Data and features

- Incidents in the database: 2,034; forecast-target incidents: 1,937 (Other / unknown and Undetermined are excluded from the target).

- Features (34): **location_time** (5); **context** (3); **weather** (12); **area_history** (14).

- Weather coverage on target incidents: temperature 91.5%, all weather features 87.9% (missing stays missing; LightGBM handles NaN).

- Area history: incidents strictly before the event date within 25 km; the hazard mix uses only incidents **closed** before the event date (cause known then), each site weighted once (sites = 1 km leader clusters).

- Leakage guards are enforced in code and tested (`tests/test_features.py`).
